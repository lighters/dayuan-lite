# 验证范围

记录日期：2026-10-15。独立实现版本：0.2.0。

## 离线验证

```bash
python3 -m unittest test_dayuan.py test_workbuddy_auth.py -v
```

用例覆盖（Python 3.11 以下跳过 pyproject 检查）：统一入口与 `--state-dir` 位置、默认状态目录与 XDG、旧目录只提示不移动、旧脚本兼容、打包声明、参数约束、只允许预定请求地址、拒绝重定向、单次提交与恢复、被拒请求同 ID 重提、服务端有界等待（只轮询不重发、到时返回当前状态、轮询失败保留任务）、上游异常响应容错、缓存命中免锁与续期锁等待、账号变化、任务上下文绑定、登录轮询、缓存、刷新前后持久化、未知刷新结果不重放、身份稳定性、MCP 握手、`instructions`、工具列表与 `readOnlyHint`。

测试凭据全部为虚构值，不运行真实登录或读取。离线测试不能证明远端服务可用。GitHub Actions 在 Python 3.9 / 3.12 / 3.13 上运行同一套测试与 `scripts/check.py`。

## 实际联机验收

| 验证 | 结果 |
| --- | --- |
| 独立状态目录、用户在官方企业微信页面扫码、云端轮询取票 | 通过 |
| 账号会话交换企微用户 token | 通过 |
| 指定群、明确时间范围的有界 A2A 查询 | 任务完成，返回远端摘要 |
| 主动刷新账号凭据、再次企微换票 | 通过，身份一致 |
| 续期后恢复同一任务 | 通过 |
| 新 MCP 进程读取同一任务 | 通过，标准错误为空 |
| 本地缓存到期后自动刷新、换票和恢复任务 | 通过，使用真实云端请求 |

最后一项人为缩短了本地缓存期限，服务端凭据当时仍有效。它证明自动触发路径可用，不是等待服务端自然过期或跨天运行的证据。

直接验证进程通过 Python audit hook 拒绝读取 `.workbuddy` / `WorkBuddy.app` 路径、创建子进程，并将 HTTP 请求限制在 `www.workbuddy.cn` 与 `qyapi.weixin.qq.com`。这些限制没有拦截到依赖尝试。测试没有停止或卸载用户已有的桌面应用。

## Grok Bot 消费端验收

2026-10-15 使用 Grok Bot 0.71.2 的桌面主助手，通过其本机执行能力调用 CLI，提交一个新的有界企业微信群查询，再按相同 request_id 查询结果。独立检查本地回执与 Grok Bot 最终回复，任务 ID 和 `completed` 状态一致，摘要已返回 Bot 对话。

此项验证由 Grok Bot 发起查询，没有以另一个客户端直接调用 A2A 代替消费端测试。实际使用的是本机 CLI；未保存私有技能、未添加长期 MCP 配置。未对 Grok Bot 进程施加前述直接验证进程的 audit hook，也不将两种验证范围混同。操作说明和通用 Prompt 见 [Bot 使用说明](BOT-USAGE.md)。

## 未证明的事项

- 原始消息数量、逐字内容和完整性；结果是远端 Agent 生成的摘要。
- 已用 `uv build` 构建 wheel，并在 Python 3.9.6 与 3.12 下通过 `uvx --from <wheel> dayuan` 运行 `--help`、`status` 和 MCP `initialize`；没有从 GitHub 地址实际执行 `pipx install` / `uvx --from git+...`，也没有用安装后的命令做真实登录和查询。
- 0.3.0 新增的 `--wait` / `wait_seconds` 服务端等待只有离线测试，尚未对真实大圆任务联机验证。
- 跨天自然到期、企业撤销授权后重新授权的长期运行情况。
- 所有企业、账号类型和 WorkBuddy 版本的通用可用性。
- 上游强制执行只读权限；本地只提供查询模板和只读提示。

公开记录省略了真实账号标识、群名、消息内容、本机路径、任务标识和全部凭据。
